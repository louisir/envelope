# Envelope 产品验收清单

版本：1.1｜初编：2026-09-11｜修订：2026-09-20｜当前状态：全部未执行。

执行基线、环境、指标与放行规则见 [验收计划](acceptance-plan.md)。每次执行复制 [记录模板](acceptance-run-template.md)。本文件是用例设计，不是通过证明。

集群具体验证步骤、Codex可执行范围与人工配合事项见 [集群验证与执行分工](acceptance-execution-guide.md)。

本文件保留 112 个父用例；首版另须完成 [主备中继专项验收](relay-ha-acceptance.md) 的 HA-01～HA-24，共 136 个父用例。旧 VPS-01～12 延后，不计入首版。存储、ACK、切换预期以 [主备协议](relay-ha-protocol.md) 为准，不能用现有 best-effort 窗口豁免数据丢失或虚假确认。

## 使用规则

- `A`=正式 Android APK 真机，`W`=正式 Windows WPF 包；`双端`=两个平台各跑一遍，不能选其中之一。测试 bridge 包只作补充。
- `全向`=A→W、W→A、A→A、W→W；主方向为前两项。单平台对照也使用不同身份。
- `混群`=含 Android 与 Windows 的群，Android / Windows 各当一次群主。涉及发送权限的用例还需轮换发送平台。
- 每行生成独立执行实例，例如 `FILE-02_A-W_N2_64MiB_RC01`；参数集与环境组合逐一记录，不用一次通过代替全部组合。基准方向未指定网络时使用 N1，NET 用例依计划指定网络。
- 表中“待”表示未执行。结果填入执行实例表，父用例仅在全部必需实例通过后汇总为通过。记录至少包括实际现象、证据路径、缺陷号、执行人、时间、包哈希与返回起点状态。
- 每节公共前置必须满足。破坏性测试仅使用已登记的测试身份、数据和环境，保留原始快照。功能入口或预期未明确时记阻塞并引用计划 D 项，不猜测通过。
