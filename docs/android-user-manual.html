Envelope Android

使用手册 / User Manual

本手册对应当前 Android 客户端，说明如何安装 APK、创建身份、用恢复词和本地备份恢复使用现场、添加联系人、发送消息和文件、使用群组，以及通过密封 / 拆封文件完成离线转交。

This manual applies to the current Android client. It covers APK installation, identity creation, recovery with a phrase and local backup, contacts, messages and files, groups, and offline transfer through sealing / opening envelope files.

适用版本：Envelope Android 1.0.1 · 复核日期：2026-09-21。完整构建号见“关于”；不同手机的安装与授权界面可能略有差异。

Applies to Envelope Android 1.0.1 · Reviewed 2026-09-21. See About for the full build identifier. Installation and permission screens may vary by device.

1. 安装和升级 / Installation and Updates

  1. 获取正式 release APK。Get the official release APK.
  2. 在 Android 系统中允许本次安装来源。Allow this installation source in Android when prompted.
  3. 打开 APK 并完成安装。Open the APK and complete installation.
  4. 升级同包名、同签名的应用时可直接安装新版 APK；已有身份、联系人、消息和设置会保留。To update an app with the same package ID and signature, install the newer APK directly. Existing identity, contacts, messages, and settings are preserved.

当前 release APK 支持 ARM64、Android 7.0（API 24）及以上；包名为 com.iamlouis.envelope。旧包 com.westwardsoft.envelope 属于独立应用，数据不会自动迁移。卸载会清除本机私有数据；操作前请导出备份并确认恢复词可用。

The release APK supports ARM64 devices running Android 7.0 (API 24) or later. Its package ID is com.iamlouis.envelope. The older com.westwardsoft.envelope package is a separate app, and its data is not migrated automatically. Uninstalling clears private app data; export a backup and confirm you have the recovery phrase first.

2. 身份和本地备份 / Identity and Local Backup

单活跃终端：一个身份当前只能选择一个活跃消息终端。迁移到 Windows 或另一台手机时，先备份并停止旧端收发，在新端恢复并核对 Key ID；这不是多端同时在线同步。One active endpoint: an identity currently has one active messaging endpoint. Before moving to Windows or another phone, back up and stop messaging on the old endpoint, restore on the new one, and verify the Key ID. This is not simultaneous multi-device synchronization.

创建身份 / Create Identity

  1. 进入底部“设置”。Open the bottom Settings tab.
  2. 在“我的身份”里填写显示名。Enter a display name under My Identity.
  3. 点击“创建身份”。App 会生成本机身份，并把 BIP39 24 词恢复词短暂显示在恢复词输入框里。Tap Create Identity. The app creates the local identity and briefly shows the BIP39 24-word recovery phrase in the recovery phrase field.
  4. 立即离线抄写恢复词；恢复词会在超时、切到后台或执行相关操作后清空。Write the phrase down offline immediately. The phrase is cleared after a timeout, when the app goes to background, or after related operations.

恢复身份和使用现场 / Restore Identity and Local State

  1. 在“我的身份”里的恢复词输入框输入原来的 24 词恢复词。Enter the original 24-word recovery phrase in the recovery phrase field under My Identity.
  2. 点击恢复词输入框下方的“用恢复词从本地备份恢复”。Tap Restore from phrase and local backup below the recovery phrase field.
  3. 选择本地备份文件。当前备份文件通常位于 Download/Envelope/backups。Choose the local backup file. Current backup files are usually under Download/Envelope/backups.
  4. 确认后，App 会用恢复词恢复身份私钥，再从备份中恢复联系人、群组、同步入口和自动备份策略。After confirmation, the app recovers the identity private keys from the phrase, then restores contacts, groups, sync entry, and auto-backup settings from the backup.
面向真实用户的恢复流程是“恢复词 + 本地备份文件”一起完成。24 词用于恢复同一个加密身份；联系人、群组、同步服务入口和自动备份策略来自本地备份。 The real-user recovery flow is recovery phrase plus local backup file. The 24-word phrase recovers the same cryptographic identity; contacts, groups, sync service entry, and auto-backup settings come from the local backup.

本地备份 / Local Backup

设置页的“本地备份”位于“我的身份”之后、“安全”之前。新备份使用当前本机身份给自己加密，会导出显示名、身份 key id、同步服务入口、联系人、群组、群成员和自动备份策略；不会保存恢复词。本地备份当前不包含聊天记录，也不包含 received / sealed 文件缓存。

Local Backup in Settings appears after My Identity and before Security. New backups are self-encrypted with the current local identity and export display name, identity key id, sync service entry, contacts, groups, group members, and auto-backup settings; the recovery phrase is not stored. Local backups currently do not include chat history or received / sealed file cache.

  1. 点击“导出本地备份”，备份文件保存到 Download/Envelope/backups。导出不需要再次输入恢复词。Tap Export Local Backup. The backup is saved to Download/Envelope/backups. Export does not require entering the recovery phrase again.
  2. 自动备份可以设置为关闭、每 6 小时、每 12 小时、每天或每 72 小时检查一次，并可保留最近 3 / 7 / 14 / 30 个备份。Auto backup can be set to off, every 6 hours, every 12 hours, daily, or every 72 hours, and can keep the latest 3 / 7 / 14 / 30 backups.
  3. 自动备份在 App 打开或回到前台时检查是否到期；到期后写入 Download/Envelope/backups。Auto backup checks whether a backup is due when the app is open or resumes to foreground; due backups are written to Download/Envelope/backups.
  4. 恢复时先输入匹配的 24 词，再点击“用恢复词从本地备份恢复”并选择备份文件。To restore, enter the matching 24-word phrase first, then tap Restore from phrase and local backup and choose the backup file.
  5. 新版 v2 备份和旧版 24 词加密 v1 备份都可以导入。Both current v2 backups and legacy v1 backups encrypted with the 24-word phrase can be imported.

3. 联系人 / Contacts

联系人通过签名 contact / IntroBundle 建立。添加前应核对 fingerprint；截图、转发或复制的 contact 只能证明数据没有被篡改，不能自动证明现实身份。

Contacts are established through signed contact / IntroBundle payloads. Verify the fingerprint before adding. Screenshots, forwarded payloads, or copied contacts only prove that the data was not tampered with; they do not automatically prove real-world identity.

二维码互加 / QR Exchange

  1. 一方在“联系人”页点击“加好友”，选择“出示二维码”。One side opens Contacts, taps Add Contact, then chooses Show QR.
  2. 另一方点击“扫描二维码”。The other side taps Scan QR.
  3. 扫描方确认 fingerprint 后保存联系人。The scanner confirms the fingerprint and saves the contact.
  4. 如果同步服务可用，出示方会收到扫描方的回传信息，并在确认后保存对方。If the sync service is available, the presenter receives the scanner's return bundle and saves it after confirmation.

粘贴 contact / Paste Contact

  1. 复制对方提供的 contact 内容。Copy the contact content provided by the other side.
  2. 在“加好友”中选择“粘贴 contact”。Choose Paste contact under Add Contact.
  3. 核对 fingerprint 后添加。Add after verifying the fingerprint.

联系人页筛选图标依次代表“全部 / 联系人 / 群聊”，可显示未读角标；联系人和群聊统一用列表入口展示。联系人可以设置备注或删除。删除联系人会尝试发送端到端加密的 contact-control 通知，对端收到后处理相应删除；这不保证对方立即在线处理。

The Contacts page uses icons for All / Contacts / Groups filters, with unread badges. Contacts and group chats are shown as unified list entries. Contacts can be noted or deleted. Deleting a contact attempts to send an end-to-end encrypted contact-control notice; the peer handles deletion after receiving it, which may not happen immediately.

4. 聊天和文件 / Chat and Files

聊天页可以选择联系人或群组。文本发送后输入框会立即清空；发送失败会留下待重试状态，后续同步或手动重试会继续投递。

The Chat page can select a contact or group. The text input clears immediately after sending. Failed sends remain as pending retry records and are retried by later sync or manual retry.

发送状态 / Send States

当前消息列表状态如下；部分 HA 状态提示在英文界面中仍显示中文，下方提供对应英文释义。可靠保存、送达和阅读是不同概念。

The message list uses the following states. Some HA prompts still appear in Chinese even in the English UI; their English meanings are provided below. Reliable storage, delivery, and reading are different concepts.

  • 发送中 / Sending：本机正在创建或提交消息。The local client is creating or submitting the message.
  • 待重试 / Pending retry：当前尚未完成投递，本机保留待重试记录。Delivery has not completed; the local retry record is retained.
  • 等待接收 / Waiting for recipient：尚无接收方送达结果，不等于对方已收到或阅读。No recipient delivery result yet; this does not mean the peer has received or read it.
  • 已送达 / Delivered：已验证接收方签名的送达结果，不代表已读。A recipient-signed delivery result has been verified; this is not a read receipt.
  • 历史发送状态（未验证）/ Historical send state (unverified)：旧记录缺少当前协议要求的证明。The old record lacks the evidence required by the current protocol.
  • 接收方已拒绝 / Rejected by recipient：接收方返回拒绝结果。The recipient returned a rejection.
  • 已过期 / Expired：信封有效期已结束，不能继续等待其送达；不代表所有磁盘副本已物理删除。The envelope lifetime has ended; do not keep waiting for delivery. This does not prove physical deletion of all disk copies.

“已可靠保存，等待收件方接收”表示已取得双副本存储证明；“等待主备可靠保存；本机保留重试副本”表示仍需重试。旧链路的“已发送”不能单独作为已送达证明。

“Reliably stored, awaiting recipient” means dual-replica storage is proved. “Awaiting reliable storage; local retry copy retained” means retry is still needed. A legacy Sent label alone is not proof of delivery.

文件 / Files

在线文件上限为 64 MiB。文件会被客户端分片、加密和校验，服务器只看到密文信封。图片和视频会在对话中显示预览；点击文件时优先调用系统默认应用打开，无法打开时再退回到保存路径。

Online files are limited to 64 MiB. Files are chunked, encrypted, and verified by the client; the server only sees encrypted envelopes. Images and videos show previews in chat. File taps prefer the system default app and fall back to the saved path if opening fails.

接收文件默认保存到 Download/Envelope/received。如果文件缓存被清空，聊天记录会标记“文件已删除”，并不再显示可打开入口。

Received files are saved to Download/Envelope/received. If file cache is cleared, chat records are marked as file-deleted and no longer show an open action.

消息管理 / Message Management

聊天列表支持加载更早消息、选择多条消息和删除本机记录。删除只影响本机数据库，不会删除其他设备上的记录。

The chat list supports loading earlier messages, multi-select, and local deletion. Deletion only affects the local database and does not delete records on other devices.

5. 群组 / Groups

创建群组至少要选择 2 位联系人；加上创建者本人，群组最少 3 人。群主创建后本机立即显示群，受邀者在与邀请者的单聊中收到群邀请消息，可以接受或拒绝。

Creating a group requires selecting at least 2 contacts; with the creator, a group needs at least 3 people. The owner sees the group locally immediately. Invitees receive invitation messages in one-to-one chats with the inviter and can accept or decline.

三种群策略 / Three Group Policies

  • 普通群：受邀者接受后成为活跃成员，可以收发群消息。Normal group: invitees become active after accepting and can send / receive group messages.
  • 验证群：成员可以在成员页核对并信任其他成员 fingerprint；发送群消息时只投递给本地信任的活跃成员。Verified group: members can verify and trust other members' fingerprints; sends only target locally trusted active members.
  • 共识群：受邀者接受后进入“等待共识”状态；活跃成员背书达到 60% 阈值后，候选成员才成为活跃成员。Consensus group: invitees enter a waiting-for-consensus state after accepting; candidates become active only after active-member endorsements reach the 60% threshold.

群成员管理 / Member Management

群详情页可以查看成员状态和 fingerprint。群主可以改群名、更新群头像 seed、邀请新成员和移除成员。普通群和验证群可以手动信任成员 fingerprint；共识群中该操作变为“背书入群”。

Group details show member state and fingerprint. The owner can rename the group, update avatar seed, invite new members, and remove members. Normal and verified groups can manually trust member fingerprints; in consensus groups, this action becomes an admission endorsement.

退群和解散 / Leave and Dissolution

点击“退出群组”后，本机会立即退出当前群聊界面并隐藏该群，再后台通知其他成员。群主退出或有效成员少于 3 人时，群会自动解散，并携带解散原因。

After tapping Leave Group, the local device exits the group chat and hides the group immediately, then notifies other members in the background. If the owner leaves or effective members fall below 3, the group dissolves automatically with a concrete reason.

群消息和群文件 / Group Messages and Files

群聊和单聊都提供“密封”入口。在线群文本、群文件和离线群组密封都会按当前策略允许的活跃成员逐一加密；每个成员收到独立密文，不使用共享群密钥。在线群发会先持久化每个子信封，部分失败时使用不变的 envelope id 安全重试仍为 pending 的子项。

Both group and one-to-one chats provide a Seal entry. Online group text, group files, and offline group sealing encrypt separately for every active member allowed by the current policy; each member receives independent ciphertext and no shared group key is used. Online fan-out durably stages every child envelope first and safely retries children still marked pending with stable envelope ids after a partial failure.

创建群、邀请/接受/退出/移除成员、共识背书、改名和头像更新也采用同级持久化：群状态、签名群事件和每个收件人的密文在一个本地事务中先写入，再连网发送。App 或网络中断后会使用原 envelope id 继续重试。

Group creation, invite/accept/leave/remove, consensus endorsement, rename, and avatar updates use the same durable policy: group state, the signed event, and every recipient ciphertext are committed in one local transaction before network delivery. After an app or network interruption, retry continues with the original envelope ids.

6. 消息同步 / Message Sync

本次发布包含 HA v2 中继引导配置和可信管理员公钥。App 校验签名集群信息并重新发现可用主节点，不需要每次故障都手动切换备用入口。自建服务必须提供匹配的信任配置，单独修改地址不能绕过签名校验。

This release includes HA v2 relay bootstrap configuration and a trusted administrator public key. The app verifies signed cluster information and rediscovers the available leader, without manually selecting a standby after every failure. A self-hosted service needs matching trust configuration; changing an address alone cannot bypass signature checks.

在“设置 → 消息同步”启用“自动同步”。需要修改时，在“中继矩阵入口”输入受信任域名或 IP，点击“保存同步服务入口”，再点击“立即同步”。

Enable Auto sync in Settings → Message sync. When changing the entry, enter a trusted domain or IP in Relay matrix entry, choose Save sync entry, then Sync now.

  • 同步更新接收路由、拉取信封、解密入库，并处理待重试消息和接收方签名结果。Sync updates receive routes, pulls envelopes, decrypts and stores messages, and processes retries and recipient-signed results.
  • “可靠保存”证明中继已满足双副本要求；“已送达”需要接收方结果，两者都不等于已读。Reliable storage proves the relay meets the dual-replica requirement. Delivered requires a recipient result. Neither is a read receipt.
  • 前台运行时拉取更积极；Android 后台限制、节电策略或强制停止可能延迟接收。重新打开 App 后可点“立即同步”。Foreground polling is more active. Android background limits, power-saving policies, or force-stopping may delay reception. Reopen the app and use Sync now.
  • 同步异常时核对网络、入口和系统时间。不要通过关闭签名校验或反复更换不可信入口解决。For sync errors, check connectivity, entry, and system time. Do not work around them by disabling verification or repeatedly selecting untrusted entries.

坏密文会被有界隔离，经过认证但缺少前置群事件的密文会延迟重试，避免阻塞其他消息。延迟队列最多 256 条、单条 12 MiB、合计 64 MiB，保留 7 天；隔离审计最多 1000 条且保留 7 天。

Poison ciphertext is handled with bounded quarantine. Authenticated ciphertext awaiting earlier group events is deferred so other messages can progress. The deferred queue is limited to 256 items, 12 MiB each, 64 MiB total, for seven days. Quarantine audit retains at most 1,000 records for seven days.

中继不可用时，已有可用 P2P 路径或离线密封仍可能使用，但依赖中继的收发与二维码回传不能保证运行。完整 HA 网络分区、容量、长期运行和双端真实设备验收仍在进行。

If the relay is unavailable, existing usable P2P paths or offline sealing may still work, but relay-dependent messaging and QR return exchange are unavailable or unreliable. Full HA partition, capacity, endurance, and real-device dual-client acceptance are still in progress.

7. 密封和拆封 / Sealing and Opening

密封是离线转交能力：发送方选择一位联系人或一个群组，把文本或文件密封成离线信封文件，然后通过邮箱、网盘、U 盘等外部工具或渠道转交。单聊信封只有该联系人能打开；群组文件使用 ENVELOPE_GROUP_STREAM_V1，为每位符合策略的活跃成员写入独立密文，因此文件大小会随收件人数增加。外部工具或渠道只负责搬运密文。

Sealing is an offline transfer capability: the sender selects one contact or group and seals text or a file into an offline envelope file, then transfers it through external tools or channels such as email, cloud drive, or USB drive. A one-to-one envelope can be opened only by that contact. A group file uses ENVELOPE_GROUP_STREAM_V1 and writes independent ciphertext for every policy-eligible active member, so its size grows with recipient count. External tools only carry ciphertext.

发送方密封 / Sender Seals

  1. 进入与某位联系人的单聊或一个有效群聊。Open a one-to-one chat with a contact or an active group chat.
  2. 点击顶部“密封”。Tap Seal at the top.
  3. 选择密封文本或本地文件。Choose text or a local file to seal.
  4. 生成的文件保存到 Download/Envelope/sealed。The generated file is saved to Download/Envelope/sealed.

接收方拆封 / Receiver Opens

  1. 进入底部“拆封”。Open the bottom Open tab.
  2. 选择离线信封文件，或粘贴 base64 内容。Choose an offline envelope file or paste base64 content.
  3. 点击“解密导入”。Tap Decrypt and Import.
  4. 拆封成功后，消息或文件会进入本机聊天记录。After successful opening, the message or file is added to local chat history.

拆封群组流时，App 会跳过写给其他成员的密文，只导入当前身份可以解密且群成员关系、epoch 和签名均有效的内容。

When opening a group stream, the app skips ciphertext addressed to other members and imports only content decryptable by the current identity with valid membership, epoch, and signatures.

Android 会接管 envelope://yourturn/open 并进入“拆封”页。也可以在文件管理器或浏览器下载列表中直接打开 .envelope 文件；系统会把文件 URI 交给 Envelope 导入。若尚未建立身份，App 会在创建或恢复身份后继续处理该文件。

Android handles envelope://yourturn/open by opening the Open tab. You can also open an .envelope file directly from a file manager or browser downloads; Android passes its URI to Envelope for import. If no identity exists yet, the app resumes the import after identity creation or recovery.

“离线”不是单纯指断网，而是指这次传输不走 Envelope 的在线投递链路，也不依赖 P2P、服务端路由或服务端离线邮箱。

Offline does not simply mean disconnected. It means this transfer does not use Envelope's online delivery chain and does not depend on P2P, server routes, or server mailbox.

8. 安全和维护 / Security and Maintenance

本地锁屏 / Local Lock

设置页可以开启“打开 App 时验证身份”。开启后，打开 App 和执行高风险操作时使用 Android 系统 PIN、密码或生物识别确认。请先在手机系统中设置可用的屏幕锁；验证失败或取消时不会解锁。Android 不使用 Windows 版的六位应用解锁码，也没有默认 123456 解锁码。

Settings can enable authentication when opening the app. Opening and sensitive actions then use Android system PIN, password, or biometrics. Set up a supported screen lock in Android first; failure or cancellation leaves the app locked. Android does not use the Windows six-digit app code and has no default 123456 unlock code.

清空文件缓存 / Clear File Cache

设置页的“清空文件缓存”会删除 Download/Envelope/received 和 Download/Envelope/sealed 下的文件，并把对应聊天记录或密封历史标记为文件已删除。

Clear File Cache in Settings deletes files under Download/Envelope/received and Download/Envelope/sealed, then marks matching chat records or sealed history as file-deleted.

诊断日志 / Diagnostic Logs

诊断日志记录操作状态、耗时、错误和网络路径，不记录消息内容、文件内容、私钥或恢复词。可以在设置页导出或清空诊断日志。

Diagnostic logs record operation status, timing, errors, and network path. They do not record message content, file content, private keys, or recovery phrases. Logs can be exported or cleared in Settings.

语言与手册 / Language and Manual

Android 界面按系统语言匹配简体中文或英文；当前没有 Windows 版的“外观与语言”选择页，使用固定浅色主题。手册同时提供中英对照，内嵌页面无需联网或启用 JavaScript。

Android selects Simplified Chinese or English from the system locale. It currently has no Windows-style Appearance and language page and uses a fixed light theme. This manual provides both languages together and needs neither a network connection nor JavaScript.

9. 常见问题 / FAQ

为什么恢复需要本地备份文件？ / Why does recovery need a local backup file?

24 词只恢复身份密钥。面向真实用户的恢复需要同时恢复联系人、群组、同步入口和自动备份策略，所以应使用“恢复词 + 本地备份文件”的完整流程。

The 24-word phrase only recovers identity keys. Real-user recovery also needs contacts, groups, sync entry, and auto-backup settings, so use the complete recovery phrase plus local backup file flow.

为什么群邀请点了接受后还要等待？ / Why is there a wait after accepting a group invitation?

接受邀请需要写入本机状态，并把状态同步给相关成员。共识群还需要活跃成员背书达到阈值后才会变为可收发消息的活跃成员。

Accepting an invitation writes local state and syncs it to related members. Consensus groups also require active-member endorsements to reach the threshold before the candidate becomes an active member.

为什么消息显示等待接收？ / Why does a message show waiting for recipient?

“等待接收”表示还没有接收方送达结果。即使已取得可靠保存证明，也要等对方上线、处理消息并返回有效签名结果后才算已送达；这不是已读状态。

Waiting for recipient means there is no recipient delivery result yet. Even after reliable storage is proved, delivery requires the peer to come online, process the message, and return a valid signed result. This is not a read receipt.

为什么文件打开失败？ / Why does file opening fail?

Android 系统和厂商文件权限策略可能不同。App 会优先用默认应用打开文件；如果系统拒绝，会退回到保存路径或提示错误。

Android system and vendor file-permission policies may differ. The app first tries the default application; if the system rejects it, the app falls back to the saved path or shows an error.
