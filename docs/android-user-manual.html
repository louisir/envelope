Envelope Android

使用手册

本手册对应当前 Android 客户端，说明如何安装 APK、创建或恢复身份、添加联系人、发送消息和文件、使用群组，以及通过密封 / 拆封文件完成离线转交。

适用版本：Envelope Android 当前版本。不同手机系统的安装确认和文件授权界面可能略有差异。

1. 安装和升级

  1. 获取正式 release APK。
  2. 在 Android 系统中允许本次安装来源。
  3. 打开 APK 并完成安装。
  4. 升级时直接安装新版 APK；已有身份、联系人、消息和设置会保留。

如果需要全新测试，先在系统设置中卸载 Envelope，再安装 APK。卸载会删除本机身份、联系人、消息、群组、密封历史和本地设置。

2. 身份和本地备份

创建身份

  1. 进入底部“设置”。
  2. 在“我的身份”里填写显示名。
  3. 生成并抄写 BIP39 24 词恢复词。
  4. 点击“创建身份”。

恢复身份

  1. 输入原来的 24 词恢复词。
  2. 填写显示名。
  3. 点击“从恢复词替换本机身份”。
  4. 确认替换后，App 会清空当前本机身份和本地聊天现场，再写入恢复出的身份。
24 词只能恢复同一个加密身份。联系人、群组、同步服务入口和本机使用现场不会只靠 24 词自动恢复；这些内容需要使用“本地备份”恢复。

本地备份

设置页的“本地备份”会用 24 词加密导出显示名、身份 key id、同步服务入口、联系人、群组和群成员。本地备份当前不包含聊天记录，也不包含 received / sealed 文件缓存。

  1. 导出前先在恢复词输入框里输入当前身份的 24 词。
  2. 点击“导出本地备份”，备份文件保存到 Download/Envelope/backups。
  3. 恢复时选择备份文件并输入匹配的 24 词。
  4. 恢复会替换当前本机身份、联系人、群组和同步服务入口。

3. 联系人

联系人通过签名 contact / IntroBundle 建立。添加前应核对 fingerprint；截图、转发或复制的 contact 只能证明数据没有被篡改，不能自动证明现实身份。

二维码互加

  1. 一方在“联系人”页点击“加好友”，选择“出示二维码”。
  2. 另一方点击“扫描二维码”。
  3. 扫描方确认 fingerprint 后保存联系人。
  4. 如果同步服务可用，出示方会收到扫描方的回传信息，并在确认后保存对方。

粘贴 contact

  1. 复制对方提供的 contact 内容。
  2. 在“加好友”中选择“粘贴 contact”。
  3. 核对 fingerprint 后添加。

联系人页支持“全部 / 联系人 / 群聊”过滤，过滤标签会显示未读角标；联系人和群聊统一用列表入口展示。联系人可以设置备注或删除。删除联系人会发送端到端加密的 contact-control 通知，对端收到后会同步删除对应联系人。

4. 聊天和文件

聊天页可以选择联系人或群组。文本发送后输入框会立即清空；发送失败会留下待重试状态，后续同步或手动重试会继续投递。

发送状态

  • 已发送：已经通过直连链路送出。
  • 待接收：已经写入服务端离线邮箱，等待对方拉取。
  • 待重试：当前路径不可用，App 会保留记录并在后续重试。
  • 已送达：对方已解密入库并返回 ACK。

文件

在线文件上限为 64 MiB。文件会被客户端分片、加密和校验，服务器只看到密文信封。图片和视频会在对话中显示预览；点击文件时优先调用系统默认应用打开，无法打开时再退回到保存路径。

接收文件默认保存到 Download/Envelope/received。如果文件缓存被清空，聊天记录会标记“文件已删除”，并不再显示可打开入口。

消息管理

聊天列表支持加载更早消息、选择多条消息和删除本机记录。删除只影响本机数据库，不会删除其他设备上的记录。

5. 群组

创建群组至少要选择 2 位联系人；加上创建者本人，群组最少 3 人。群主创建后本机立即显示群，受邀者在与邀请者的单聊中收到群邀请消息，可以接受或拒绝。

三种群策略

  • 普通群：受邀者接受后成为活跃成员，可以收发群消息。
  • 验证群：成员可以在成员页核对并信任其他成员 fingerprint；发送群消息时只投递给本地信任的活跃成员。
  • 共识群：受邀者接受后进入“等待共识”状态；活跃成员背书达到 60% 阈值后，候选成员才成为活跃成员。

群成员管理

群详情页可以查看成员状态和 fingerprint。群主可以改群名、更新群头像 seed、邀请新成员和移除成员。普通群和验证群可以手动信任成员 fingerprint；共识群中该操作变为“背书入群”。

退群和解散

点击“退出群组”后，本机会立即退出当前群聊界面并隐藏该群，再后台通知其他成员。群主退出或有效成员少于 3 人时，群会自动解散，并携带解散原因。

群消息和群文件

群聊没有密封入口。群文本和群文件通过在线聊天发送，客户端按当前有效成员逐一加密 fan-out；每个成员收到的是独立密文信封。

6. 消息同步

同步服务入口是中继矩阵的 bootstrap 地址。进入“设置”里的“消息同步”，在“同步服务入口”输入域名或 IP 并保存。App 会通过该入口刷新签名节点清单，然后在可用节点之间自动切换。

  • 自动同步会注册当前设备 route、拉取 mailbox、ACK 已解密消息并查询送达状态。
  • “立即同步”会立刻执行一次注册、拉取、ACK 和待重试消息处理。
  • App 前台运行时会更积极地拉取 mailbox，以降低消息到达延迟。
  • 节点清单和节点身份都需要签名校验；节点不能解密消息内容。

如果未配置同步服务，点对点直连和离线密封仍可使用，但 mailbox、送达回执、二维码互加回传和多入口节点池不会运行。

7. 密封和拆封

密封是点对点离线转交能力：发送方选择一位联系人，把文本或文件密封成只有该联系人能打开的离线信封文件，然后通过邮箱、网盘、U 盘等外部工具或渠道转交。外部工具或渠道只负责搬运密文。

发送方密封

  1. 进入与某位联系人的单聊。
  2. 点击顶部“密封”。
  3. 选择密封文本或本地文件。
  4. 生成的文件保存到 Download/Envelope/sealed。

接收方拆封

  1. 进入底部“拆封”。
  2. 选择离线信封文件，或粘贴 base64 内容。
  3. 点击“解密导入”。
  4. 拆封成功后，消息或文件会进入本机聊天记录。

“离线”不是单纯指断网，而是指这次传输不走 Envelope 的在线投递链路，也不依赖 P2P、服务端路由或服务端离线邮箱。

8. 安全和维护

本地锁屏

设置页可以开启“打开 App 时验证身份”。开启后，打开 App 和执行高风险操作时会使用系统 PIN、密码或生物识别确认。

清空文件缓存

设置页的“清空文件缓存”会删除 Download/Envelope/received 和 Download/Envelope/sealed 下的文件，并把对应聊天记录或密封历史标记为文件已删除。

诊断日志

诊断日志记录操作状态、耗时、错误和网络路径，不记录消息内容、文件内容、私钥或恢复词。可以在设置页导出或清空诊断日志。

关于页

关于页显示版本信息、APK 签名证书 SHA-256 和内置用户手册入口。用户手册随 APK 打包，不需要单独的网页服务。

9. 常见问题

为什么 24 词恢复后没有联系人？

24 词只恢复身份密钥。联系人、群组和同步服务入口属于本机使用现场，需要用本地备份恢复。

为什么群邀请点了接受后还要等待？

接受邀请需要写入本机状态，并把状态同步给相关成员。共识群还需要活跃成员背书达到阈值后才会变为可收发消息的活跃成员。

为什么消息显示待接收？

这表示消息已经进入服务端离线邮箱，对方上线并完成同步后才会变为已送达。

为什么文件打开失败？

Android 系统和厂商文件权限策略可能不同。App 会优先用默认应用打开文件；如果系统拒绝，会退回到保存路径或提示错误。
