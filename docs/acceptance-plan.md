## 1. 验收目标与结论边界

验收回答的是：普通用户拿到正式候选包后，能否独立完成安装、建立身份、添加联系人、跨端通信、群组协作、离线转交、备份恢复，并在故障后保持数据与权限正确。

本计划由当前仓库源码、设计文档、用户手册和测试入口梳理而来；它不是已完成验收报告。所有产品用例初始为“未执行”。本次仅运行了静态契约检查，没有构建候选包、安装客户端、操作真机、压测或变更服务端。

建议先按本计划取得“限定平台范围内可试点”结论，再完成 7 个自然日的小范围用户试点，最后决定正式发布。涉及密码学安全的结论限定为已测威胁场景；不将功能验收描述为独立安全审计。

### 2.1 开测前要关闭的口径问题

这些是从文档与实现边界发现的待验证风险，不是已经复现的缺陷。负责人在用例执行前给出统一预期；否则关联用例记“阻塞”。不能执行后为了通过而修改标准。

| 编号 | 要确认的产品口径 | 依据与关联用例 |
| --- | --- | --- |
| D-01 | 支持的 Android API / ABI、Windows 版本与最低硬件；后台到达与通知承诺 | Android minSdk=24、构建脚本默认 arm64；不据此宣称所有 API≥24 或 Windows 系统已验证。见 REL-02、UX-07 |
| D-02 | 共识群初始邀请的引导规则、邀请者隐含背书、普通候选人的 60% 取整 | Windows `ConsensusInitialInviteBootstrapApplies` 对特定 epoch=1 初始邀请使用阈值 1；一般阈值与初始入群分开测。见 GRP-05/06 |
| D-03 | 群主退出是否必定解散；有效成员计数是否包括 pending / accepted | Windows `DissolutionReasons` 独立检查 `owner_left` 和人数；手册与设计部分措辞不同。见 GRP-10 |
| D-04 | 存储状态与接收结果分离；delivered 必须来自持久入库后的收件方签名，不是清除 ACK 或已读 | 规范见主备协议第 4、6、7 节；待实现/验证。见 MSG-04、NET-07/08、HA-09/10/11 |
| D-05 | 离线文件可支持的实际大小、旧单体容器限制及群发限制提示 | 在线 64 MiB / 4 MiB 分片；Android 旧单体导入 32 MiB；群发暂存密文 256 MiB。手册“任意大小”须改成实际验证范围或明确资源边界。见 FILE-02、OFF-03、GRP-12 |
| D-06 | 旧终端迁移后的停止方式，是否存在技术撤销保证 | 当前为单活跃终端约定；不得承诺未实现的远程踢下线 / 多设备同步。见 REC-05/06 |
| D-07 | Windows 包签名、可信分发、移动目录后文件关联和卸载方式 | 配对包可自包含，不能据此推定 Authenticode 签名或安装器存在。见 REL-03/04/07 |
| D-08 | 主备确认、降级、仲裁/fencing、恢复与 RPO/RTO | 规范由主备协议定义；主设计HA-D1选择etcd三成员+双SQLite，参数为待测基线，需按HA-01～24实现验证，不能沿用旧best-effort豁免 |

## 3. 范围

### 3.1 本轮必须覆盖

- 正式候选 APK 与 Windows x64 自包含 ZIP 的安装、升级、首次使用、文档和包完整性。
- 身份创建 / 恢复 / 替换、本地锁、Contact / IntroBundle、二维码与指纹确认。
- Android↔Windows 双向为主，Android↔Android、Windows↔Windows 为协议对照；文本、文件、离线信封、备份分别互通。
- Normal / Verified / Consensus 三类群：邀请、成员生命周期、权限、逐收件人加密、控制事件和可靠重试。
- P2P、route retry、mailbox、回执、多节点切换；断网、重启、乱序、重复、坏密文、队列满等异常。
- 两业务副本及独立仲裁下的双副本确认、客户端自动切换、intro/路由/结果完整恢复；单副本降级和无多数派行为按 HA 协议。
- `.envelope` 文件关联、`envelope://yourturn/open`、Android `content://`、冷启动 / 热启动 / 无身份 / 锁定状态。
- 本地存储保护、日志泄漏、恶意输入、容量、可用性、可恢复性、受控服务端故障与用户试点。

### 3.2 不作为已交付能力要求

同一身份多端同时在线同步、聊天记录与缓存跨端迁移、仅用 24 词找回联系人与群组、iOS / Linux 产品客户端、音视频 / 通用 TURN 或 WebSocket 代理产品、MLS、前向保密 / 入侵后安全、DHT、开放跨运营方互联及动态全网选点。既有 Iroh 传输中继依赖仍须登记和验收，不因其使用某种传输协议而排除。

原版将 mailbox 跨节点强一致性整体排除的表述已修订：本版不交付通用分布式数据库，但主备协议定义的有序提交、双副本可靠确认及单业务节点故障 RPO=0 是必过要求。

上述边界必须在入口和手册中明确。已有图片 / 视频文件的发送和预览仍在范围内。YourTurn 只验收交给 Envelope 的文件及启动链路；MBSim、寄存器重建和完整挑战业务不归本轮。真实 YourTurn 环境未提供时，模拟来源通过只能关闭客户端用例，不能关闭真实集成用例 EXT-08。

## 4. 环境、身份与数据准备

### 4.1 最低可执行矩阵

| 代号 | 配置 | 用途 |
| --- | --- | --- |
| A1 | Android ARM64 真机，目标用户常用系统和厂商 ROM | 主链路、相机扫码、content URI、SQLCipher、前后台 |
| A2 | 第二台 Android 真机，不同系统版本或厂商，含低内存设备 | A↔A、厂商差异、资源压力；如承诺 API 24，增加该下界验证 |
| W1 | Windows x64 真机，目标主力系统，已配置 Windows Hello / 系统凭据 | 主链路、系统锁、资源管理器关联 |
| W2 | 第二个干净 Windows x64 环境，无开发 SDK / .NET Runtime | 自包含包、W↔W、普通用户权限、升级；虚机证据单独标注 |
| S1 / S2 | 两个隔离 Envelope Server 节点，同候选兼容版本 | route、mailbox、节点签名、切换 / 重启 / 同步；记录实际限额与 TTL |
| Q | 独立第三故障域的控制投票成员，组件与版本冻结 | 与 S1/S2 控制成员提供多数派；无信封正文，不替代业务副本 |
| 额外隔离实例 | 需要时增加独立设备或 Windows 用户 / VM | 5 个 active 成员加 1 个候选人的共识阈值边界；不复用同一身份并发 |

兼容性补充必须包含发行范围内的系统下界和上界、Windows 100% / 150% / 200% DPI，以及有 / 无可用系统验证器。未测的平台标注“未验证”，不从 WPF TargetFramework、Android minSdk 或模拟器通过推导支持范围。

每个日常通信端分配独立测试身份 `U-A1 / U-A2 / U-W1 / U-W2`。迁移场景才复制同一身份，并先停止旧端。群主角色在 Android 与 Windows 间轮换；移除 / 解散测试使用独立群，避免污染其他用例。恢复词、密钥仅用于隔离测试，放入受控秘密存储，不写入报告或 Git。

### 4.2 网络矩阵

| 网络 | 布置 | 需要证明 |
| --- | --- | --- |
| N1 | 同一局域网，允许 P2P | 实际采用 direct，不能只凭“发送成功”判断路径 |
| N2 | Android 移动网络与 Windows 独立网络，P2P 不可达 | route retry / mailbox 回退及恢复 |
| N3 | 接收方离线 30 分钟，发送方在线 | mailbox 暂存、重启后拉取、入库与回执 |
| N4 | 双端断网 / 飞行模式，再恢复 | pending 持久化与主动同步恢复 |
| N5 | 受控 200 ms 延迟、2% 丢包、短时断连、网络切换 | 重试正确性及用户可见状态；保存故障配置 |
| N6 | 停 S1、保留 S2+Q；隔离业务/控制链路、失去多数派、恢复旧主 | 按 HA 协议验收副本水位、fencing、RPO/RTO、降级、去重和终态；不能按旧 best-effort 标准放行 |

N5/N6 只在测试网和隔离节点注入。先固定目标与恢复步骤，不影响其他业务。服务器配额、保留期、轮询策略必须在报告中写实际值，不能把部署文档示例当现网配置。

### 4.3 标准数据集

- 文本：中文、英文、emoji、多行、空白、长文本（1 KiB / 64 KiB 及实现边界）。每条带运行编号与顺序号；记录唯一逻辑消息 ID，避免仅靠正文计数。
- 在线文件：0 B、1 B、4 MiB−1 B、4 MiB、4 MiB+1 B、64 MiB−1 B、64 MiB、64 MiB+1 B；准备图片、视频、PDF、随机二进制。预先登记字节数与 SHA-256。
- 离线流：文本、64 MiB、256 MiB、1 GiB 文件；覆盖单人及群组，记录群成员数导致的体积增长。1 GiB 是本轮建议测试点，不是无限文件大小承诺。
- 路径：中文、空格、同名文件、长文件名、只读目录、目标文件已存在、磁盘不足；危险路径、伪造 MIME、截断与篡改信封在沙箱测试目录中处理。
- 恢复：当前 v2、受支持的历史 v1 备份；Android v11 / v13 数据库副本与当前结构；旧 Windows 状态样本。样本记录来源版本与哈希，不使用真实用户库。
- 规模：1,000 联系人、10,000 消息（最大单会话至少 5,000）、20 个群；群成员 3 / 10 / 20 人。额外身份可用协议生成器，但目标 UI 和接收端必须使用真实产品包。

## 6. 工程检查入口与证据分层

以下命令为后续执行入口，除静态契约检查外本次未运行。应在已冻结的隔离工作副本执行，保存命令、工具版本、退出码、起止时间和完整日志。

```powershell
# 仓库根目录；静态契约检查
.\scripts\verify-client-parity.ps1

# Rust 协议、FFI 和服务端相关测试
cargo test --workspace

# Android 宿主检查
Push-Location .\apps\envelope_app
flutter analyze
flutter test
Pop-Location

# 同版本双端候选包，版本仅为示例，执行时替换为冻结的候选版本
# 默认 Android release、Windows self-contained；不要加跳过验证参数
.\scripts\build-client-pair.ps1 -AppVersion v1.0.0.202609110001 -BuildName 1.0.0

# 单独运行 WPF 控制台验证（先构建相同源码的 release FFI 并确认复制到输出目录）
dotnet run --project .\apps\envelope_windows\Envelope.Windows.Tests -c Release

# 使用实际 manifest / APK / 公钥路径核验 Android 更新包
# .\scripts\verify-android-update-manifest.ps1 -ManifestPath <路径> -ApkPath <路径> -PublicKeyPath <路径>
```

配对构建只统一版本参数，不自动证明发布包内容完整。Windows 单独构建脚本默认 framework-dependent，正式通用交付须明确使用自包含包。Android 默认只构建 arm64；其他 ABI 必须单独纳入构建与验收。

| 证据层 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| L1 源码 / 静态检查 | 接口、常量和代码结构存在 | 编译、运行、实际行为 |
| L2 单元 / 宿主集成测试 | 在测试环境中的协议与状态机结果 | Android SQLCipher、系统权限和真实 UI |
| L3 包验证 | APK / ZIP 版本、签名、依赖、哈希、资源正确 | 干净机器启动和完整用户操作 |
| L4 正式包设备验收 | 指定设备、网络和步骤下的真实用户结果 | 未测试系统、未测试负载或长期生产可靠性 |
| L5 试点 / 运维演练 | 限定规模用户和故障场景下的发布依据 | 无限规模、独立安全审计或强一致性保证 |

启用 ADB bridge 的测试 APK 单独命名、哈希和保管。现有三机脚本默认会清理聊天存储（除非使用 `-SkipClearChatStores`），两机脚本也可清理数据和 logcat；运行前核对目标 serial、参数和测试数据。故障注入包只能给内部原子性提供辅助证据，关键路径必须在禁用 bridge 的最终 release APK 上通过 UI 重跑。APK 内 `.so` 与同次 Gradle stripped native 输出比较，不能与未 strip 的 `.so` 直接作等值判断。

## 7. 建议质量门槛（开测前冻结）

以下性能、容量、用户体验指标是本计划提出的验收目标，不是仓库已经承诺或测得的数据。若目标设备需要调整，应在 G0 由负责人记录新值和理由；功能正确性、安全隔离和数据完整性门槛不得以降指标方式放行。

| 项目 | 建议门槛与测量方法 |
| --- | --- |
| 消息正确性 | 每个必测方向在 N1/N2/N3 各发送 100 条唯一文本；在线文件边界集逐个完成；预期集合与收件集合匹配，无重复可见消息、错收、静默丢失或虚假成功 |
| 群消息 | 3 / 10 / 20 人群按合法收件人集合逐人对账；拒绝、未通过共识、未信任、已移除成员不收到不应收到的新内容；已获授权的历史密文不宣称可远程撤回 |
| 主链路时延 | N1 前台文本端到端 P95≤3 秒，N2 双端在线 P95≤10 秒；每方向至少 100 样本，从点击发送至接收端入库可见，单独记录 ACK 与 UI 展示时间 |
| 离线恢复 | N3 接收端重开并点击立即同步后，100 条积压文本 60 秒内完成入库与对账；不把后台推送作为前提 |
| 启动与 UI | 每设备冷启动 20 次，至可交互页面 P95≤5 秒（排除用户输入系统凭据的时间，另记锁界面耗时）；10,000 条记录下会话打开 P95≤2 秒、分页≤1 秒，各 30 次，无持续>2秒无反馈卡顿 |
| 文件与流处理 | 所有成功输出字节数 / SHA-256 一致；N1 64 MiB 单聊在线文件建议≤120秒；大文件导入内存不随整文件大小线性增长，无 OOM / ANR / 半成品伪成功；记录设备峰值内存和耗时 |
| 稳定性 | 72 小时、双端及混合群，每 5 分钟一组文本、每小时一个 4 MiB 文件、每 6 小时一次受控断网；零崩溃 / ANR、零丢失 / 重复 / 越权；周期清理后空闲内存相对首小时基线增长≤20%（同一测法），异常增长需定位 |
| 资源与降级 | 配额满、磁盘满、权限取消、服务不可用均给出可理解提示；已有数据不损坏，恢复条件后可继续；不得自动无限重试耗尽电量 / 磁盘 |
| 安全 | 无正文 / 私钥 / 恢复词进入诊断与服务日志；认证失败不绕过本地锁；篡改 / 错误收件人 / replay 不产生业务副作用 |
| 可用性试点 | 5～10 名首次使用者，按手册完成建身份→互加→跨端收发→备份 / 离线导入；至少90%的指定任务无需开发介入，所有身份、文件与删除范围误解单独评估 |

性能统计报告必须给样本数、P50/P95/max、失败数；不把失败样本删除后只报告成功时延。超时按失败计入，数据集和网络条件不一致的结果不得直接合并。

## 8. 准入、缺陷与退出规则

### 准入

- G0 基线、支持范围、产品口径、负责人、测试服务与设备已登记；测试身份与恢复样本就绪。
- 工程测试通过，最终 APK / ZIP 可验证并在干净环境启动；正式 APK 不开放测试 bridge。
- Android / Windows 同一候选版本，服务器兼容版本固定；没有阻碍主链路的已知缺陷。

### 用例优先级与缺陷严重性

| 级别 | 用例优先级 | 缺陷例子 |
| --- | --- | --- |
| P0 / S0 | 发布硬门槛 | 身份 / 私钥泄漏、越权解密、不可恢复数据损坏、锁绕过、错误收件人 |
| P1 / S1 | 核心产品能力 | 安装失败、跨端收发失败、重试丢失 / 重复、备份不可恢复、群权限错误、伪送达 |
| P2 / S2 | 非核心体验与兼容性 | 非核心排版、低频可恢复问题；实际影响严重时升级为 S0/S1 |

P 表示计划优先级，S 表示发现后的实际严重性，不机械一一对应。用例可为 `未执行 / 通过 / 失败 / 阻塞 / 不适用`；“有代码”“自动化通过”“等待设备”不能填产品用例通过。

### 发布退出

1. 所有适用 P0/P1 用例在最终候选包上 100% 通过；无未关闭 S0/S1，无适用 P0/P1 阻塞。统计粒度为“用例×方向×必要环境实例”，不是父用例数量。
   HA-01～24全部必须通过，不能作为可选多节点能力排除。已可靠保存数据的单节点零丢失、无虚假送达与旧主隔离属于硬门槛。
2. P2 通过率≥95%（分母为全部适用实例，未执行 / 阻塞仍计入）；剩余必须有缺陷号、影响、绕行方案、负责人、修复版本及产品负责人书面接受。
3. 不适用必须附功能排除或平台范围的依据并签字；不能用不适用掩盖没有环境或失败。主备HA是当前首版承诺，不得由执行人员自行删去；若以后产品明确改变范围，应另立验收版本。YourTurn 若经确认从发布范围删除，须同步关闭宣传并标记有限范围结论。
4. 完成 72 小时稳定性、备份恢复演练、服务故障恢复、正式包 UI 回归及用户试点。代码 / 二进制发生变化后，重新登记哈希，复验关联模块和全部 P0/P1 主链路。
5. 产品、QA、客户端、服务端负责人共同签署“通过 / 有条件通过（仅限已接受的 P2）/ 不通过”。无签署、无设备证据或版本不一致不得视为产品验收完成。

## 9. 证据保存与交付

每次执行复制 [执行模板](acceptance-run-template.md)，在受控目录保存 `artifacts/acceptance/<候选版本>/<运行编号>/`；仓库已忽略 artifacts，需另行归档到团队证据库，不能只依赖本地目录。

目录建议包含：`baseline/`（源码和包清单）、`environment/`（设备与服务配置脱敏副本）、`engineering/`、`cases/<实例ID>/`（前后截图、诊断、对账、哈希）、`defects/`、`metrics/`、`signoff/`。每条用例记录起点、具体步骤、预期、实际、完成证据、返回起点状态；照片 / 截图避免暴露恢复词和真实联系人。

最终交付：签署报告、实例结果总表、候选 APK / 自包含 ZIP 及 SHA-256、签名与 manifest 验证记录、缺陷与遗留风险表、兼容性矩阵、性能原始数据、稳定性报告、恢复演练和试点反馈。二进制包本轮尚未生成或认证。
